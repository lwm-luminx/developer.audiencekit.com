Changelog

One changelog for the whole SDK from 0.24.0 on. Earlier releases are in swift/CHANGELOG.md (through 0.23.0) and android/CHANGELOG.md (through 0.19.0).

0.67.0 (2026-11-14)

Section titled “0.67.0 (2026-11-14)”
  • Reporting an intimate image shared without consent (regulatory review, 2026-11-14). ReportCopy.reasons / REASONS gain “Intimate image shared without consent” (ReportCopy.intimateImage / INTIMATE_IMAGE). The API gives a report with that reason a 48-hour deadline and tells the admins so, which is what the US Take It Down Act asks of an app that hosts people’s photos. Apps that list ReportCopy.reasons show it with no change.

0.66.0 (2026-11-14)

Section titled “0.66.0 (2026-11-14)”
  • No silent attestation failures (Rick, 2026-11-14: “build out warnings about no SafetyNet or DeviceCheck and that it prevents login on the login paths so no silent errors”). deviceAttestationNotice() on iOS and Android answers the warning a login screen shows when the device can’t attest (no App Attest, no Play Integrity, or no attestor at all): a DeviceAttestationNotice with reason, blocksSignIn, title and message. It reads the audience’s policy from GET /v1/token/methods (deviceAttestation, audience_kit_api security hardening PR); the message says outright when sign-in is blocked. Nil when the device can attest or the audience doesn’t check. A refused sign-in still throws deviceNotTrusted, whose message from the API now says why and what to do.

0.65.0 (2026-11-14)

Section titled “0.65.0 (2026-11-14)”
  • Sessions expire (Rick, 2026-11-14: “build in exp to tokens”). The API now puts an exp on session tokens (90 days for a member, 30 for staff; audience_kit_api security hardening PR) and expiresAt is no longer null. On iOS the SDK refreshes by itself: before a call, when the token has under 30 days left or ran out up to 30 days ago, it trades it at POST /v1/token/refresh and stores the new credential (no SessionEvent; it retries at most hourly when offline). refreshSession() does it on demand. Venue device credentials are left alone, they end with their grant. Android has refreshSession() already but does not yet call it by itself; that is a follow-up, and tokens minted before this are good until 2027-02-15.
  • The iOS Keychain item is now kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, so a session token is not carried to another device by a backup restore or device transfer. Existing items change the next time the credential is saved (a sign-in or a refresh).

0.64.0 (2026-11-14)

Section titled “0.64.0 (2026-11-14)”
  • Publisher ads are the publisher’s (Rick, 2026-11-14: “when showing soapbox content the user will acknowledge that the publisher is responsible for their ad relationship”; “this relationship is to support the publishers and let them continue to support writers and content”; “we take no cut like performers”). PublisherAdsCopy gives the one-time note a reader acknowledges before their first Soapbox story (title, body(appName:), “I understand” / “Not now”), and PublisherAdsAcknowledgement remembers who acknowledged it by user ID: on iOS in UserDefaults plus the private iCloud key-value store, on Android in private shared preferences (com.audiencekit.android.PublisherAdsAcknowledgement). Nothing goes to the server; a guest is never recorded, so they see it each time. Same words on iOS and Android.

0.63.0 (2026-11-14)

Section titled “0.63.0 (2026-11-14)”
  • Ad-free audiences (Rick, 2026-11-14: “begin building advertising”). advertising() reads whether the audience is open to sponsors or ad-free (AudienceAdvertising, .open / .adFree, OPEN / AD_FREE on Android) and who pays for it (adFreeSponsor). adFreeNote gives what “Cards you see” can say (“Ad-free, thanks to …”). An ad-free audience’s layouts already come without promoted cards, so the apps don’t filter anything themselves. Needs audience_kit_api #560; older servers throw, so treat a failure as open. An unknown mode reads as open. Same on iOS and Android.

0.62.0 (2026-11-14)

Section titled “0.62.0 (2026-11-14)”
  • Readable text on an audience’s accent (Rick, 2026-11-14: “the lime color of hack different has white (low contrast text on it)”). Branding.Theme.onAccent(dark:) and foreground(on:dark:) give the color for text and icons on an accent (or any token) fill: the theme’s on-<token> when it reaches WCAG AA 4.5:1 on that fill, otherwise near-black (#111411, RGBAColor.inkOnLight / INK_ON_LIGHT) or white, whichever has more contrast. RGBAColor gains relativeLuminance, contrastRatio(with:) and readableForeground. Apps that skin from /v1/branding should use these instead of white on the accent: on Hack Different’s lime (#c5f467) white is 1.3:1 and the derived dark text is 14.6:1. Same on iOS and Android.

0.61.0 (2026-11-14)

Section titled “0.61.0 (2026-11-14)”
  • Flagged messages for Velvet (Rick, 2026-11-14: “build some amount of the message flag / decision UX into velvet for message that are flagged (simplified)”). FlaggedMessage, FlaggedMessageAction (Dismiss, Remove, Warn, Cooldown, Escalate, Ban), the shared GraphQL (FlaggedMessages.query / reviewMutation with their variables and responses) and FlaggedMessageCopy, in AudienceCore on iOS and com.audiencekit on Android, word for word. They run on the staff endpoint, so StaffKit sends them; availableActions leaves only Dismiss and Escalate for the room’s own people. Needs audience_kit_api #544.

0.60.0 (2026-11-14)

Section titled “0.60.0 (2026-11-14)”
  • Android parity with Hot Mess iOS 2.7 (Rick, 2026-11-14: “fill the gaps”). Kotlin titles(personId) reads a performer’s community titles (pageant crowns, Imperial Court reigns, club titles, chapter leads; the API’s PersonOffice::TITLES), reigning first, as the Swift titles(personID:) does; PersonOffice.detail is the place and years under each. Kotlin AppCheck and GraphQLOperationLog port “Check the app” from Swift: the same steps, OK/EMPTY/FAIL/SKIP marks and plain-text report, with the client’s recent failed requests (the log is a GraphQLMonitor and can pass events on to another; the Android AudienceKitClient(context, …) factory now takes a monitor). Compose apps draw their own screen from AppCheck.state.

0.59.0 (2026-11-13)

Section titled “0.59.0 (2026-11-13)”
  • GitHub and GitHub Projects (Rick, 2026-11-13: “integrate github sdk and projects into hack different”). The API’s new github module reads the community’s GitHub organization with the audience’s own GitHub App: its public repositories and its public Projects (v2) with each item’s Status. gitHubCommunity(repositories:) reads the organization, repositories and projects for a GitHub tab; gitHubProject(number:) reads one project’s README and items, which GitHubProject.columns groups into a board by Status; myGitHubItems() lists the items assigned to the signed-in person’s connected GitHub account. GitHubCopy has the shared words. Audiences without a GitHub App get nil/empty, so apps can call them unconditionally. Needs audience_kit_api with the github module.

0.58.0 (2026-11-12)

Section titled “0.58.0 (2026-11-12)”
  • Local news on Now (Rick, 2026-11-12: “a few articles from publishers cards into now for your locale”). CardKind.articlesLocale (ARTICLES_LOCALE on Android) is the API’s new articles.locale card: when the viewer’s locale has recent articles from its publishers (Soapbox, including teasers from publishers’ RSS feeds), the Now layout ranks a “Local news” card after Coming up. It arrives as a PostsCard with the locale’s id (LayoutCard.localeID), so the layout query is unchanged and works against any API; load the articles with articles(about: .locale(id), first: 3) (articlesAbout(ArticleTopic.Locale(id), first = 3) on Android). An API without the kind never sends it.

0.57.0 (2026-11-11)

Section titled “0.57.0 (2026-11-11)”
  • StaffApp.velvet(venueID:audienceID:eventID:) (and velvet(venueId, audienceId, eventId) on Android) links to an event at a venue: audiencekit-velvet://venue?id=<venue>&audience=<audience>&event=<event>. Velvet 1.10 opens the venue and then the event’s page, so Hot Mess can say “Open in Velvet” on events at venues the person manages.

0.56.0 (2026-11-11)

Section titled “0.56.0 (2026-11-11)”
  • Community titles (Rick, 2026-11-11: titles reuse offices, audience_kit_api #518). OfficeKind gains pageantTitle, courtTitle, clubTitle and chapterLead, with isTitle: a Hot Mess crown or Imperial Court reign, a club title (Mr. Leather), a Hack Different chapter lead. offices(at:localeID:status:titles:) keeps only titles (true) or only civic offices (false), filtered in the SDK so it works against an API from before titles; OfficeHolder.titles and civicOffices split a person’s page; [PersonOffice].only(titles:). titles(personID:) reads just someone’s titles (a PersonTitles query), for a performer’s page in Hot Mess.
  • graphql/schema.graphql is copied again from the API’s next (the title kinds and titles: arguments).

0.55.0 (2026-11-11)

Section titled “0.55.0 (2026-11-11)”
  • Community chats (Rick, 2026-11-11: link Hack Different’s hackerspaces and conferences to the chats they use). SocialLink.isCommunityChat picks out discord, matrix, irc and mailing_list links, networkName names the network (“Matrix”, “IRC”, “Mailing list”), and communityChats on Event and VenueDetail lists them. Events carry their own links (Event.socialLinks, the API’s new Event.socialLinks, such as DEF CON’s Discord or 40C3’s Matrix space): event(id:) asks for them, lists leave them out to keep their cost down, and an API without the field gets the query again without it.
  • CommunityChatLinks (AudienceKitUI): “Join on Discord”, “Join on Matrix”, “Join on IRC” and “Mailing list” buttons that open each chat.
  • graphql/schema.graphql updated from the API.

0.54.0 (2026-11-11)

Section titled “0.54.0 (2026-11-11)”
  • AudienceKit’s own cards and credit (Rick, 2026-11-10: “I’m my own first advertising client”). Promo cards in the new audiencekit category are labelled “From AudienceKit”, can’t be hidden, and carry staffApp (velvet, backstage or focus) when they’re about getting a staff app. CardFilter.installedStaffApps skips those on a phone that already has the app, checked on the device, so the server never learns. On an API without PromoCard.staffApp the layout asks again without it.
  • StaffApp (AudienceCore, and com.audiencekit.StaffApp on Android): Focus, Velvet and Backstage with their names, App Store and Android IDs, URL schemes, download links (audiencekit.com/apps//) and deep links (StaffApp.velvet(venueID:audienceID:), StaffApp.backstage(personID:audienceID:)). StaffAppLink (AudienceKitUI) opens the app when it’s installed and its download page when it isn’t (“Open in Velvet”, “Join the Velvet beta”, “Get Backstage”); StaffApps.installed(context) in audiencekit-android checks the packages.
  • PlatformCredit and PlatformCreditFooter (AudienceKitUI): “Powered by AudienceKit”, “A Love Wins Media product”, audiencekit.com’s Privacy, Terms, Child safety and Contact pages, “Bring AudienceKit to your venue” and the copyright line, with links tagged utm_source=<bundle>&utm_medium=app. The same words and links on Android.

0.53.0 (2026-11-11)

Section titled “0.53.0 (2026-11-11)”
  • “Check the app”, moved out of the DNC demo app so every app gets it (Rick, 2026-11-11: shared features belong in the SDK). GraphQLOperationLog (AudienceCore) is a GraphQLMonitor that keeps the last 100 operations and their errors, writes failures to the unified log (category graphql), and passes everything on to the app’s own monitoring. AppCheck runs the app’s steps (each one OK, empty, failed or skipped, timed) and builds a plain-text report; AppCheckView (AudienceKitUI) is the screen, with “Copy report” and the recent failed requests. Empty screens caused by a refused query, which apps hid behind try? (DNC’s events, Hack Different’s catalog), now show up there.
  • New AudienceKitTesting library for apps’ unit tests: GraphQLStub answers an audience’s GraphQL from a closure, records each request, hands out a signed-in member AudienceSession, and withinComplexityBudget(perItem:) refuses an over-budget page with the API’s own error, so a page size the server would turn away fails in a test.
  • CI checks the documents the SDK builds from a SchemaShape (events, locales, offices, Soapbox and others) against the API schema too: RenderedDocumentsTests writes them out and the graphql job validates them. The source check skipped all 16 of them, including every query the DNC demo app reads.
  • License 1.2 (Rick, 2026-11-08): no license of any kind is granted beyond the express grant (no implied, estoppel or trademark rights); misrepresenting the SDK or Love Wins Media’s work (authorship, origin, notices, endorsement) is expressly prohibited and a material breach; Modifications may be made only in a fork of the repository, after written notice to Love Wins Media (a “Derived work notice” issue). The Earlier versions section now points to the README’s list, so the same text can be used in StaffKit. Package metadata says LicenseRef-AudienceKit-SDK-1.2.
  • License: the SDK moves from the MIT License to the AudienceKit SDK License (Rick, 2026-11-06), now version 1.1 (Rick, 2026-11-08). The SDK is source-available, not open source: it may be used only in apps that connect to AudienceKit as hosted by Love Wins Media, and every other use is prohibited unless Love Wins Media, Inc. permits it in a signed written agreement and issues an audience ID or token for that use. 1.1 also adds patent terms and a 30-day cure on notice, and lists exactly which releases stay MIT (Swift tags through 0.41.0, source through 0.42.0, the audience-kit gem 0.1.0 and 0.1.1). Package metadata now says so: LicenseRef-AudienceKit-SDK-1.1 in the gemspec, composer.json and pyproject.toml (with the License :: Other/Proprietary License classifier), SEE LICENSE IN LICENSE in the npm package (which now ships the file, as the Python release does), and a POM <licenses> entry on every Maven publication.

0.52.0 (2026-11-10)

Section titled “0.52.0 (2026-11-10)”
  • Civic organizing in Swift, for the DNC demo app (Rick, 2026-11-10; the API’s PersonOffice, audience_kit_api #477). AudienceSession.offices(at:localeID:status:) gives someone’s representatives and candidates, most local first (the API’s root offices), each with its holder and their DonationTarget; officeHolder(id:) reads one person’s page (offices, Donate target, website, social accounts, upcoming events, and the voter issues they share with the signed-in person). New models: OfficeKind (unknown kinds kept), OfficeStatus, PersonOffice, OfficeLocale, OfficeHolderSummary, OfficeHolder, DonationTarget, SocialAccount. An audience without offices gets none back (the documents drop fields its schema lacks). Kotlin follows.
  • graphql/schema.graphql is copied again from the API’s next (offices, nested locales, donation targets).

0.51.0 (2026-11-10)

Section titled “0.51.0 (2026-11-10)”
  • App Review sign-in is never offered in an App Store install (Rick, 2026-11-10). Swift: InstallSource.offersReviewCode (false only for .appStore; App Review runs builds in StoreKit’s sandbox like TestFlight, so reviewers still see it), InstallSource.signedAppTransaction (the AppTransaction JWS), AudienceSession.reviewCodeAvailable() (install source plus GET /v1/token/review) and signIn(reviewCode:device:), which sends the AppTransaction as app_transaction so the API refuses the code for an App Store install (403, reason store_install). Android is unchanged: Play can’t tell a reviewer’s install from anyone else’s, so the code stays gated by App Review mode there.

0.50.0 (2026-11-10)

Section titled “0.50.0 (2026-11-10)”
  • Device attestation at sign-in (Rick, 2026-11-10; the API’s doc/DEVICE_ATTESTATION.md, audience_kit_api #459). Every sign-in now asks POST /v1/token/attestation for a one-use challenge and sends proof over it as attestation, so an audience can refuse tokens minted anywhere but its genuine app on a genuine device. Apps change nothing beyond updating the SDK:
    • Swift: AppAttestAttestor (App Attest / DeviceCheck), on by default on iOS (AudienceSession’s new deviceAttestor: parameter, AppAttestAttestor.platformDefault). The first sign-in from an install attests a Secure Enclave key; later ones send an assertion. The key ID is kept in UserDefaults (UserDefaultsAttestationKeyStore). Simulators send unsupported without a challenge round trip.
    • Kotlin: DeviceAttestor and AudienceKitClient(deviceAttestor = …); audiencekit-android adds PlayIntegrityAttestor (Play Integrity, com.google.android.play:integrity), on by default in AudienceKitClient(context, configuration).
    • When the audience enforces attestation and the device fails, sign-in throws AudienceKitError code DEVICE_NOT_TRUSTED (Swift) or AudienceKitException.DeviceNotTrusted (Kotlin, a new subclass). When the API doesn’t know an App Attest key (a restored backup), the SDK makes a new one and retries once. When the audience has attestation off, or the API is older, nothing extra is sent.

0.49.0 (2026-11-10)

Section titled “0.49.0 (2026-11-10)”
  • Swift: read-only chat rooms. A room that mirrors a provider’s channel (the API’s read-only Discord bridge) sends ChatRoomEvent.readOnly(replyURL:) right after .joined: signed-in people read and report its messages, sending fails, and replyURL opens the channel on Discord to reply there. The subscription now asks for ChatJoined’s readOnly and replyUrl, so it needs an API with them (audience_kit_api #428). .readOnly is a new case, so exhaustive switches over ChatRoomEvent need it. Kotlin follows.

0.48.0 (2026-11-09)

Section titled “0.48.0 (2026-11-09)”
  • Soapbox (Swift and Kotlin): articles from the audience’s publications (a newspaper such as QSaltLake, a candidate) and op-eds readers send them. articles(localeID:publicationID:first:) is a locale’s or a publication’s news, article(id:) reads one with its Markdown body and what it’s about, articles(about:) (Kotlin articlesAbout) lists a venue’s, event’s, person’s or locale’s “In the news”, publications() / publication(id:) back a publication page, myOpEds() shows where the signed-in person’s op-eds stand, and submitOpEd(...) sends one. Articles carry the publication’s disclosure (show it above the article) and teaser (link to canonicalUrl instead of a body). Audiences without the Soapbox module get empty lists and nil, never an error. SoapboxCopy keeps the apps’ words the same. Needs audience_kit_api #436 (on next).
  • graphql/schema.graphql is the API’s consumer schema as of next, with Soapbox.

0.47.0 (2026-11-09)

Section titled “0.47.0 (2026-11-09)”
  • Connect Discord (Swift and Kotlin): someone who signed in another way (Sign in with Apple, say) connects their Discord account so the audience’s Discord bridge knows them as the same person. DiscordConnection makes the verifier and the API’s authorize URL and reads the audiencekit-discord://callback hand-back; connectDiscord(...) posts it with connect: true and stores the session the API returns; connectedDiscord() reads me { self { signedInWithDiscord discordUsername } } (nil on an API older than those fields). iOS also gets AudienceKitUI‘s ConnectDiscordButton (iOS 16.4+, ASWebAuthenticationSession); Android apps declare an intent filter for scheme audiencekit-discord, host callback. ConnectDiscordCopy keeps both apps’ words the same. Needs audience_kit_api #427.

0.46.2 (2026-11-08)

Section titled “0.46.2 (2026-11-08)”
  • The audience-less endpoint’s docs and tests name the API’s /v1/staffql: selfQL (/v1/selfql) is gone (Rick, 2026-11-08). The pathed /v1/audience/<id>/staffql stays the same sign-in scoped to one audience. No code change.

0.46.1 (2026-11-08)

0.25.0 (2026-10-20)

Section titled “0.25.0 (2026-10-20)”

GraphQL operations can be followed in an app’s monitoring (New Relic, say), by name, over HTTP and over the cable.

  • Every GraphQL request carries X-APOLLO-OPERATION-TYPE (query, mutation, subscription) and X-APOLLO-OPERATION-NAME (the operationName passed, else the name in the document). New Relic’s mobile agents record both with each network request, so HTTP operations show up by name with no app changes.
  • GraphQLMonitor, an optional hook the app hands the SDK: Swift AudienceSession(..., monitor:), Kotlin AudienceKitClient(..., monitor =). It hears about each HTTP operation (GraphQLOperationEvent: name, type, endpoint, duration, error).
  • Swift: the session’s cables report to the same monitor. Operations multiplexed over the one WebSocket get their own events (subscribed, result with time to first result, ended, rejected), and the socket gets CableSocketEvents (connected, disconnected with the reason and whether it reconnects). The agents can’t see inside the socket, so this is the only record of those operations.
  • GraphQLOperationEvent.describe(query:operationName:) reads an operation’s type and name from its document.
  • Swift APIRequest and Kotlin APIRequest take extra headers.
