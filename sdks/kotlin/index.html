AudienceKit Android SDK

Kotlin client for the AudienceKit API, for Android apps (and any JVM): sign people in with Facebook, then read an audience’s venues, people, locales and events over GraphQL, and its branding over REST. It matches the Swift SDK call for call.

  • Kotlin coroutines: every call is a suspend function that’s safe on the main thread
  • Facebook Login stays in your app: the SDK takes the access token Facebook gives you
  • Three libraries:
    • com.audiencekit:audiencekit-core (in ../core): a Kotlin Multiplatform prototype containing GraphQL variables, coordinates and endpoint routing, shared by JVM and Apple targets.
    • com.audiencekit:audiencekit: the client, models and GraphQL. Plain JVM, so it runs in unit tests without an emulator. Depends only on kotlinx-coroutines and kotlinx-serialization, and talks HTTP over HttpURLConnection.
    • com.audiencekit:audiencekit-android: KeystoreTokenStore and DeviceDescription.current(context). Android 8.0 (API 26) and up.

Configure a client

Section titled “Configure a client”

Create one client for the app (in your Application, or your DI graph) and share it.

Setting What it does
baseUrl The API. http://10.0.2.2:3000 reaches a local server from the emulator.
host Names the audience. Sent with sign-in so the API checks the Facebook token against the audience’s Facebook apps and binds the session to the audience, and used to fetch branding. <subdomain>.admin.audiencekit.com works for every audience; the audience’s own domain works once it’s verified. Without a host, the API only accepts tokens from the AudienceKit platform Facebook app.
audienceId The audience’s UUID. Optional: the client reads it from the session token, or looks it up from host.
facebookAppId The Facebook app the build uses (production, staging or development). It must be one of the audience’s apps.

AudienceKitClient(context, configuration) keeps the session token in a KeystoreTokenStore: encrypted with an AES key held in the Android Keystore, and usable from background work. Leave its preferences file (com.audiencekit.session) out of your backup rules. The core constructor, AudienceKitClient(configuration, tokenStore, transport), takes any TokenStore (InMemoryTokenStore is for tests and previews) and any HttpTransport, so you can route the SDK through your own OkHttp client.

Sign in

Section titled “Sign in”

Run Facebook Login in your app, then exchange its access token:

This calls POST /v1/token, whose JSON says everything about the session (userId, audienceId, role, endpoint, venueDeviceId, expiresAt), so the app never decodes the JWT. The SDK stores the token and the audience id and sends the token on every later call as Authorization: Bearer <token>. refreshSession() re-issues the token (POST /v1/token/refresh) for the same session.

Sign-in can fail with AudienceKitException.SignInRejected (the Facebook token is invalid, or from an app the audience doesn’t use) or AudienceKitException.SignInFailed.

Sign in with Apple

Section titled “Sign in with Apple”

Android has no Sign in with Apple of its own, so AppleWebSignIn runs Apple’s web sign-in in a Custom Tab with a Services ID. Apple posts the result to the API (/v1/token/apple/callback), which hands it back to your app on audiencekit-apple://callback, so declare that on the activity that takes it:

The nonce never leaves the app (Apple gets its SHA-256), and the API signs in with Apple only with it, so a token picked up in the browser can’t be used elsewhere. The Services ID’s return URLs must include the callback URL; see the API’s doc/TOKENS.md, “Sign in with Apple on Android”.

Session ends

Section titled “Session ends”

Sessions don’t expire, but they end when the person signs out elsewhere or removes the app from Facebook. Then any call throws AudienceKitException.Unauthorized, the client deletes the token, and sessionEvents emits SessionEvent.SESSION_ENDED. Collect it from one place to send the person back to sign-in:

client.signOut() forgets the session on the device. Log out of Facebook in your app as well.

Read the audience

Section titled “Read the audience”

Objects’ id fields are the records’ UUIDs, the same IDs the REST endpoints and node(id) take; there is one ID per record everywhere.

Run any other operation and decode it into your own @Serializable type:

Build variables with graphQLVariables("id" to venueId, "limit" to 10), which converts strings, numbers, booleans, enums, lists, maps and Coordinates. If the response has errors, the call throws AudienceKitException.GraphQL with each error’s message, path and extensions. Decoding ignores fields the SDK doesn’t know, so new API fields don’t break shipped apps; pass json = … to decode with your own settings.

Branding

Section titled “Branding”

Branding is public, so you can skin the app before sign-in:

DesignTokens carries the whole design system: every theme’s colours (DesignTokens.hotMess, .hotMessDark, .light, .dark), the presets by key (DesignTokens.presets["hot_mess"]), and Spacing, Radius, Size, Opacity and Typography. It’s generated from admin/src/design/tokens.json by bun run tokens in admin/, so don’t edit it by hand. Overlay the audience’s branding.theme overrides on its preset’s colours.

Errors

Section titled “Errors”

Every failure is an AudienceKitException:

AudienceKitException When
NotSignedIn No stored session for a call that needs one.
Unauthorized The API rejected the session (401). The session has ended.
SignInRejected, SignInFailed POST /v1/token refused the Facebook token (401), or failed (400).
Forbidden 403, e.g. a session bound to another audience.
NotFound 404: no such audience, record or host.
Http Any other unsuccessful status.
Network No response: offline, timeout, TLS. cause is the IOException.
Decoding The response wasn’t what the SDK expected.
GraphQL The GraphQL response had errors.
MissingConfiguration, TokenStorage Setup problems.

Cancelling the calling coroutine cancels the request.

Development

Section titled “Development”

With JDK 17 (selected by the monorepo’s mise configuration):

audiencekit-android is only part of the build when the Android SDK is found (ANDROID_HOME, ANDROID_SDK_ROOT, or sdk.dir in local.properties), so the JVM library builds with just a JDK. Tests stub HTTP with an HttpTransport, plus a local HTTP server for UrlConnectionTransport, so they run offline.
