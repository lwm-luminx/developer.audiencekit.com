AudienceKit Swift SDK

Swift client for the AudienceKit API: sign people in with Facebook, then read an audience’s venues, people, locales and events over GraphQL, and its branding over REST.

  • Swift 6, async/await, everything Sendable
  • No dependencies. Facebook Login stays in your app: the SDK takes the access token Facebook gives you.
  • iOS 16+, macOS 13+, and Linux (without the keychain store)

Installation

Section titled “Installation”

Add the package with Swift Package Manager:

and depend on the products you need (in Xcode, File › Add Package Dependencies… with the same URL):

Product What it is Depends on
AudienceCore The session: configuration, sign-in, the credential and its stores, GraphQL transport, branding, errors nothing
AudienceKit The member-facing API: venues, people, locales, events, RSVPs, location, cover AudienceCore
AudienceKitUI SwiftUI building blocks and the generated DesignTokens AudienceCore, AudienceKit

Configure a client

Section titled “Configure a client”
Setting What it does
baseURL The API. http://localhost:3000 for a local server.
host Names the audience. Sent with sign-in so the API checks the Facebook token against the audience’s Facebook apps and binds the session to the audience, and used to fetch branding. <subdomain>.admin.audiencekit.com works for every audience; the audience’s own domain works once it’s verified. Without a host, the API only accepts tokens from the AudienceKit platform Facebook app.
audienceID The audience’s UUID. Optional: the client reads it from the stored credential, or looks it up from host.
facebookAppID The Facebook app the build uses (production, staging or development). It must be one of the audience’s apps.
coverPassPrefix The prefix on cover pass QR codes, HMC1 by default.
feeLabel What to call the audience’s fee on a cover charge, e.g. “Hot Mess fee”.

KeychainCredentialStore keeps the session’s Credential in the keychain (readable after first unlock, so background launches can use it), as a versioned JSON item; an item from an older SDK reads as no session. InMemoryCredentialStore is for tests and previews, and you can write your own CredentialStore.

Sign in

Section titled “Sign in”

Run Facebook Login in your app, then exchange its access token:

This calls POST /v1/token, which answers with the session’s Credential: token, userId, audienceId, role, the GraphQL endpoint the token was issued for, venueDeviceId and expiresAt. The SDK stores it and sends the token on every later call as Authorization: Bearer <token>, together with X-AudienceKit-API-Version: 2026-10-11, the API contract it speaks (AudienceKitSDK.apiVersion). The response has no profile; read me() for the person’s name.

Sign-in can fail with code SIGN_IN_REJECTED (the Facebook token is invalid, or from an app the audience doesn’t use) or SIGN_IN_FAILED (the message is the API’s).

A credential minted elsewhere (a venue device’s, one the platform console handed over) becomes the session with try await client.adopt(credential:), and a platform-console session moves to an audience with try await client.switchAudience(to: audienceID) (POST /v1/admin/choices). GraphQL then goes to the API instance and audience the credential names.

Session ends

Section titled “Session ends”

Sessions don’t expire, but they end when the person signs out elsewhere or removes the app from Facebook. Then any call throws an AudienceKitError with code UNAUTHENTICATED (error.isUnauthenticated), the client deletes the credential, and sessionEvents yields .sessionEnded. Every access to sessionEvents is its own subscription, so watch it from as many places as you like:

The event comes once per session, however many calls the API refused at the same time, and a refusal of an older token never ends a newer sign-in. A 403 (FORBIDDEN, e.g. no staff role) or a network failure doesn’t end the session.

Connections the SDK doesn’t make itself (a Server-Sent Events stream) carry client.sessionToken() and the same headers as every call (request.setAudienceKitHeaders(environment:token:)). When the server refuses that token there (the stream answers 401), hand the token back and the session ends the same way:

Realtime: one cable for every subscription

Section titled “Realtime: one cable for every subscription”

GraphQL subscriptions (chat rooms, notifications) ride one Action Cable websocket. Keep one AudienceCable for the app and subscribe every feature on it; the socket opens with the first subscription and closes after the last one ends, so subscriptions that live while the app is in the foreground keep it open exactly then. The client makes one wired to its session: the socket opens on the API instance the stored credential names (wss://<origin>/connection; the configured base URL before sign-in), its handshake carries Authorization: Bearer <token> and the same X-AudienceKit-* headers as every call, and a connection the server closes as unauthorized ends the session like an HTTP 401. Pass endpoint: .staff for a staff tool’s subscriptions, and url: to point a development build at a local cable.

A socket that hears nothing for 12 seconds (Action Cable pings every 3) counts as dropped. The cable reconnects with backoff from one second to half a minute, then subscribes and executes every live operation again. Call disconnect() on signing out.

try await client.signOut() forgets the session on the device, yields .signedOut, then revokes the token with DELETE /v1/token. The device is signed out even when that call fails (offline, say); the thrown error means the token may still be alive on the server. Log out of Facebook in your app as well.

Read the audience

Section titled “Read the audience”

Objects’ id fields are the records’ UUIDs, the same IDs the REST endpoints and node(id:) take; there is one ID per record everywhere.

Run any other operation and decode it into your own type:

Variables are [String: GraphQLValue], which you can write as literals: variables: ["id": "…"]. Dates decode from ISO 8601 strings (fractional seconds or not) with the default decoder, JSONDecoder.audienceKit; pass your own decoder for other strategies. If the response has errors, the call throws an AudienceKitError whose code and message are the first error’s (extensions.code: UNAUTHENTICATED, FORBIDDEN, NOT_FOUND, INVALID, RATE_LIMITED, CONFLICT, INTERNAL), with INVALID’s per-field messages in fields and every error in errors.

Branding

Section titled “Branding”

Branding is public, so you can skin the app before sign-in:

AudienceKitUI.DesignTokens (add import AudienceKitUI) carries the whole design system: every theme’s colours (DesignTokens.hotMess, .hotMessDark, .light, .dark), the presets by key (DesignTokens.presets["hot_mess"]), and Spacing, Radius, Size, Opacity and Typography. It’s generated from the AudienceKit design system’s tokens, so don’t edit it by hand. Overlay the audience’s branding.theme overrides on its preset’s colours.

Mobile operations

Section titled “Mobile operations”

The calls the Hot Mess apps make for the signed-in member:

reportLocation records where the member is and says where that is: the venue they’re in, else their locale and its nearbyVenues. Select the fields you need, including the module mixins the screen reads (such as venue { friends { list { name } } } or audience { me { ping { friendPings { id } } } }), and decode into your own type. $position is a CoordinatesInput: here.coordinatesInput(beaconMajor: beacon?.major), or here.graphQLValue with no beacon.

The API also serves venues { venue(id:) }, events { event(id:) }, people { person(id:) } and locale(id:) by UUID, audience { venues { list(near:) } } nearest first with each distance, and each locale’s and venue’s upcoming events (events { upcoming { nodes { … } } }: mixins, whose lists are Relay connections).

Cover

Section titled “Cover”

A venue’s coverCharge is tonight’s price; when payable, the member can pay it in the app and gets a pass:

Make the pass’s QR code on the device, so it works with no signal. It changes every 30 seconds (Apple platforms, CryptoKit) and starts with the audience’s coverPassPrefix:

Door staff see venues in doorVenues() and check codes with scanAdmission(venueID:code:), which returns an outcome (.admit, .reEntry, .expired, …) and a message for the door.

Lineup and karaoke

Section titled “Lineup and karaoke”

A venue’s lineup tonight is its running order, which the venue advances like a slide deck. Karaoke singers are on it too: entries with role .singer and their signup as songRequest, called up when the venue advances to them.

AudienceKitUI draws it: VenueHostRow (the host on now, their links and Tip), VenueLineupStrip (the non-singers, as a strip) and KaraokeQueue (the singers, the user’s signup and Sign up to sing, or a partner’s Join and QR code when the venue runs KaraFun). Theme them with .audiencePreset(theme.preset). The singer is pushed when they’re up next (kind: singer_up_next).

Song requests work the same way without a lineup entry: the request waits in the venue’s song queue until the host plays it, then it’s played or skipped.

SongRequestsSection draws them: Now playing, Request a song (greyed with the venue’s reason while closed) and the user’s requests with Withdraw. The user is pushed when their song plays (kind: song_request_playing).

Update prompts

Section titled “Update prompts”

TestFlight testers and App Store users on an old build hear about the new one, and builds the API no longer supports are stopped with a way forward. Where the app came from is StoreKit 2’s AppTransaction environment only: sandbox installs update in TestFlight, production ones on the App Store, and Xcode builds (or anything StoreKit can’t verify) never see a prompt. The builds come from the API’s release config, GET /v1/app_release?app=<bundle id>.

It checks when the app comes to the foreground, at most once a day (checkNow() for “Check for updates”), and keeps the config so it works offline. Below the channel’s oldest working build is a full-screen blocking prompt; below its latest, a sheet that “Not now” skips until the next build; a TestFlight install without the TestFlight app is told to get the app from the App Store. List itms-beta and itms-apps in the app’s LSApplicationQueriesSchemes.

To draw your own, read AudienceUpdates.prompt (or prompts, onPrompt) and use UpdateSheet, UpdateScreen or UpdateBanner; for UIKit keep an AudienceUpdatePromptPresenter. installSource, status, lastChecked and UpdateText fill an About screen.

Errors

Section titled “Errors”

Every failure is an AudienceKitError: a code, a message for the person, and detail where there is any (status, fields, errors, underlying, minimumSDKVersion). Switch on error.code against AudienceKitError.Code:

Code When
UNAUTHENTICATED The API rejected the session (401). The session has ended.
FORBIDDEN 403, e.g. a session bound to another audience, or no staff role.
NOT_FOUND 404, or a GraphQL error saying so.
INVALID Refused input; fields has the per-field messages.
RATE_LIMITED, CONFLICT, INTERNAL As the API says.
NOT_SIGNED_IN No stored credential for a call that needs one.
SIGN_IN_REJECTED, SIGN_IN_FAILED POST /v1/token refused the login (401), or failed (400).
UPDATE_REQUIRED, UNSUPPORTED_API_VERSION The API no longer serves this SDK (426) or its API version (400).
HTTP Any other unsuccessful status (status).
NETWORK No response: offline, timeout, TLS (underlying).
DECODING The response wasn’t what the SDK expected.
GRAPHQL A GraphQL error with no extensions.code.
MISSING_CONFIGURATION, STORAGE Setup problems.

A code the SDK doesn’t know is passed through as the API sent it. The constants AudienceKitError.unauthorized, .forbidden, .notFound, .notSignedIn and .signInRejected are the values the SDK throws, for tests.

Server-defined enums (RSVPState, Presence, PaymentProvider, PersonEventInvolvement.Relationship, AudienceKitEnvironment) keep a value the SDK doesn’t know as .unknown(String) and send it back unchanged; known lists the cases the SDK does know.
