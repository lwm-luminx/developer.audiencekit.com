Core

The audience itself and what every module builds on: users, the viewer’s state (me), tags and tribes, theme, locales and the platform’s administration.

acceptTerms
input: TermsAcceptInput!		 TermsAcceptPayload Records that the signed-in user agreed to the terms of use, which forbid objectionable content and abuse. The apps ask before anyone chats. requires users:write:self
blockUser
input: BlockedUserAddInput!		 BlockedUserAddPayload Blocks someone: neither sees the other’s chat messages, presence, pings or whereabouts any more. They aren’t told. The audience’s admins are, in the console’s Reports queue. requires users:write:self
cancelSafetyAlert
input: SafetyAlertCancelInput!		 SafetyAlertCancelPayload Cancels your open safety alert: you’re OK now. Staff on shift are told. requires users:write:self
checkContacts
input: ContactsCheckInput!		 ContactsCheckPayload Checks the hashed contacts from the viewer’s phone (ContactMatching: SHA-256 hex of “first|last|+E164”, one per number; contacts without a first and last name left out) and turns matching on. Replaces their last check. Once a day. requires users:write:self
createCalendarFeed
input: CalendarFeedCreateInput!		 CalendarFeedCreatePayload The signed-in user’s calendar subscription link in this audience (doc/CALENDAR_SYNC.md), made on first ask. reset gives it a new secret, so the old link stops working. requires users:write:self
deleteAccount
input: AccountDeleteInput!		 AccountDeletePayload Deletes the signed-in user’s account and everything recorded about them (see UserDataEraser), and signs them out everywhere. It can’t be undone. requires users:write:self
deleteCalendarFeed
input: CalendarFeedDeleteInput!		 CalendarFeedDeletePayload Ends the signed-in user’s calendar subscription link in this audience: calendar apps subscribed to it stop getting updates. requires users:write:self
disableContactMatching
input: ContactMatchingDisableInput!		 ContactMatchingDisablePayload Turns contact matching off: deletes their number, match name and every code, at once, and withdraws requests they sent that nobody answered. Friends they made stay. requires users:write:self
identifyWithTribe
input: TribeIdentifyInput!		 TribeIdentifyPayload Identifies the signed-in user with one of the audience’s tribes, or changes whether that’s private. Private is the default: only people in the same tribe see it, and it is always private unless audience.publicTribes is on. Refused past audience.tribeCap tribes. requires users:write:self
leaveTribe
input: TribeLeaveInput!		 TribeLeavePayload Removes the signed-in user from one of the tribes they identify with. Nothing is kept. requires users:write:self
recordCardViews
input: CardViewsRecordInput!		 CardViewsRecordPayload Records that promoted cards were on screen. Send only the cards actually shown. requires users:write:self
registerDevice
input: DeviceRegisterInput!		 DeviceRegisterPayload Stores the push notification token for the device this session signed in on. requires users:write:self
remindSafetyAlert
input: SafetyAlertRemindInput!		 SafetyAlertRemindPayload Sends your open safety alert again: staff on shift hear it again, and the venue’s managers too. At most every 30 seconds. requires users:write:self
reportContent
input: ContentReportInput!		 ContentReportPayload Reports a message, person, venue, ping, photo, post or comment to the audience’s admins, who see it in the console’s Reports queue at once. Optionally blocks the person responsible, when there is one: a message’s sender (not for posts as the venue or a person), the person themself, a ping’s sender, a comment’s author. requires users:write:self
reportLocation
input: LocationReportInput!		 LocationReportPayload Records the user’s position and returns the venue they’re in, or what’s near them. requires users:write:self
reportVenueOpen
input: VenueOpenReportInput!		 VenueOpenReportPayload Says a venue reported closed is still open. A reviewer decides; the venue is back in tonight’s views sooner when enough people (or its staff) say so. requires users:write:self
respondToFriendRequest
input: FriendRequestRespondInput!		 FriendRequestRespondPayload Answers a friend request someone sent the viewer. Accepting makes them friends and tells the sender; “Not now” hides it and tells nobody. requires users:write:self
sendFriendRequest
input: FriendRequestSendInput!		 FriendRequestSendPayload Asks someone contact matching found to be friends, and pushes them. Asking someone who already asked the viewer accepts their request. requires users:write:self
sendSafetyAlert
input: SafetyAlertSendInput!		 SafetyAlertSendPayload Tells the staff on shift at the venue you’re at that you feel unsafe (only while the app places you there). Where you are and what is going on are optional; send it first and add them after (updateSafetyAlert). While your alert there is open, sending again adds to it. requires users:write:self
sendSafetyAlertMessage
input: SafetyAlertMessageSendInput!		 SafetyAlertMessageSendPayload Sends a message in a safety alert’s private thread: from the guest who sent it while it is open, or from staff at its venue. Never shown in venue chat. requires users:write:self or chat:moderate:mine or chat:moderate:venue or audience:moderate:*
setChatInitials
input: ChatInitialsSetInput!		 ChatInitialsSetPayload Shows the signed-in user’s initials in chat rooms instead of their photo, or their photo again. requires users:write:self
setContactMatchName
input: ContactMatchNameSetInput!		 ContactMatchNameSetPayload Changes the first and last name friends match the viewer on. Their own codes follow at once. requires users:write:self
setRecentChatPush
input: RecentChatPushSetInput!		 RecentChatPushSetPayload Turns on or off pushes about new messages in chat rooms the signed-in user left in the last 30 minutes (at most one every 10 minutes per room). Off until they turn it on. requires users:write:self
setTribes
input: TribeSetInput!		 TribeSetPayload Replaces the signed-in user’s tribes here with these, for the picker’s Done. Tribes they keep keep their privacy; new ones are private. Refused, changing nothing, past audience.tribeCap tribes. requires users:write:self
startContactPhoneVerification
input: ContactPhoneVerificationStartInput!		 ContactPhoneVerificationStartPayload Saves the name friends will match the viewer on and texts a six-digit code to their mobile number (verifyContactPhone). Up to five codes a day, 30 seconds apart. requires users:write:self
submitContribution
input: ContributionSubmitInput!		 ContributionSubmitPayload Suggests a missing venue or event, a correction, a closure, a tag or a performer for the audience’s listings. A reviewer decides; nothing changes until they approve. Local rules are corrected with submitLocalRulesCorrection, by venue staff. requires users:write:self
unblockUser
input: BlockedUserRemoveInput!		 BlockedUserRemovePayload Unblocks someone the signed-in user blocked. requires users:write:self
updateSafetyAlert
input: SafetyAlertUpdateInput!		 SafetyAlertUpdatePayload Adds where you are and what is going on to your open safety alert. Concerns add to the ones you picked; left-out arguments keep what you said. requires users:write:self
verifyContactPhone
input: ContactPhoneVerifyInput!		 ContactPhoneVerifyPayload Checks the code startContactPhoneVerification texted. Right, the number is theirs: it moves off any other account that had it. Five tries per code. requires users:write:self

edgeChanged

id: ID!		 EdgeChanged! Follows a record’s lists (a venue’s events, an event’s appearances): an event whenever a member joins, leaves or changes, carrying the member as you may read it. Name an edge to hear about one list only. requires audience:read:self or venues:read:venue

Section titled “Objects”

AppReleaseChannel

Section titled “AppReleaseChannel”

Object

What an iOS app’s update prompts tell installs from one StoreKit 2 environment (TestFlight or the App Store): the build to offer and the oldest one that still works. Null fields mean no opinion.

Field Type Description
availableAt ISO8601DateTime When latestBuild starts being offered (CI waits for TestFlight to process it).
latestBuild Int The newest build (CFBundleVersion).
latestVersion String Its version, e.g. 2.1.
minimumBuild Int Builds below this must update before they can be used.
notes [String!]! What’s new, one line each.
updatedAt ISO8601DateTime When it last changed.
updatedBy String Who changed it last: the CI token, or “admin”.

AppReviewCode

Section titled “AppReviewCode”

Object

A code App Review signs in with and the test account it signs in as: the demo venue’s code (the main reviewer, in Hot Mess and the staff apps) or an AppReviewCode linked to its own account.

Field Type Description
code String The code; null for one set before codes were kept.
expiresAt ISO8601DateTime When the code stops working.
id ID! Its UUID.
label String! What the code is for.
removable Boolean! Whether removeAppReviewCode can remove it: not the demo venue’s main code, which createAppReviewCode or resetAppReview replaces.
userEmail String The email address of the test account it signs in as.
userName String The name of the test account it signs in as.

AudienceAppReview

Section titled “AudienceAppReview”

Object

An audience’s App Review period and review codes for its apps.

Field Type Description

codes [AppReviewCode!] This audience’s App Review codes and the test accounts they sign in as. requires audience:admin:*
grant VenueDeviceGrant The main App Review code status (the demo venue grant). requires audience:admin:*
until ISO8601DateTime When the App Review period ends.

Section titled “AudienceMobileApp”

Field Type Description

testflightRelease AppReleaseChannel iOS: what TestFlight installs of main’s archives are told about updates.
testflightUrl String iOS: the public TestFlight invite link.
